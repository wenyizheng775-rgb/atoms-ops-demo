# Atoms Ops Demo · 笔试作品说明

**作者：郑文怡**

## 一、作品简介

本项目是一个参考 Atoms 核心体验设计的 AI Native 应用构建 Demo，重点实现通过自然语言驱动应用生成，并将生成结果以可交互的网页形式展示。

在基础生成与预览流程之外，我进一步加入了 Gatekeeper 自动化门禁、版本发布、回滚和审计能力，希望验证的不只是 AI 能否生成页面，还包括生成结果如何经过检查、管理版本并形成可追踪的交付流程。

**核心流程：需求输入 → AI 生成 → 实时预览 → 迭代修改 → 自动预检 → 发布与版本管理。**

- **在线 Demo：** http://134.175.134.145:18080/
- **GitHub 源码：** https://github.com/wenyizheng775-rgb/atoms-ops-demo

## 二、实现思路与关键取舍

### 1. 以核心用户流程为主线

围绕「从自然语言到可运行应用」设计主流程，优先打通需求输入、AI 生成、页面预览和持续迭代，再补充发布门禁与版本管理能力，避免在有限开发时间内陷入复杂的平台功能建设。

### 2. 结合 LLM 与确定性规则

使用 DeepSeek API 根据用户需求生成应用，并支持继续通过自然语言修改结果。对于发布前可以明确判断的规则，则使用程序执行检查，而不是完全依赖模型自行判断，以提高流程的可验证性。

### 3. 让生成结果具备基本的交付能力

采用单页 HTML 作为生成产物，通过 iframe `sandbox` 进行预览；发布时保存版本快照，并提供回滚和审计记录，让应用从生成、预览延伸到版本管理与交付。

### 4. 控制实现复杂度

优先实现可以实际体验的核心闭环，暂不追求完整复刻 Atoms 平台。数据使用 JSON 文件持久化，适配当前单实例 Demo；复杂的多 Agent 协作、多租户和完整生产部署体系不作为本轮重点。

## 三、当前完成情况

目前实现的主要能力包括：

- **注册登录：** 邮箱注册 / 登录，会话 Cookie；项目按账号隔离（公开页仍可匿名访问）。
- **AI 应用生成：** 接入 DeepSeek API，根据自然语言需求生成应用，并支持迭代修改。
- **可视化预览：** 在网页中展示生成结果，支持体验页面交互。
- **自动化门禁：** 对生成产物进行规则检查，并将检查结果用于发布决策。
- **版本发布：** 保存发布快照，提供可访问的公开 Demo 页面。
- **版本回滚：** 支持恢复历史版本。
- **审计追踪：** 记录关键操作，便于查看应用的变更与交付过程。
- **数据持久化：** 使用 `data/store.json` 保存项目相关数据，支持刷新后恢复。

本项目的发布能力面向 Demo 页面和版本快照，不等同于生产集群部署。

## 四、如果继续投入时间，我会如何扩展

我会优先提升核心流程的可靠性与安全性，再逐步扩展 Agent 能力和协作场景。

**P0｜可靠性与安全性**

补充核心流程自动化测试，完善生成失败、门禁不通过、发布异常和回滚失败等场景的处理；进一步加强生成代码的隔离与资源限制。

**P1｜Agent 执行能力**

将生成、检查和修复过程拆分为可追踪的工具执行步骤，让每一步的输入、输出和执行结果更加清晰；在确有收益的任务中探索多步骤 Agent 协作。

**P2｜数据与协作能力**

根据部署规模将文件存储升级为数据库，进一步支持用户身份、项目权限、多人协作和更完整的版本管理。

优先级判断的原则是：先确保核心链路稳定、结果可验证，再增加系统复杂度和功能广度。

## 本地启动

```bash
cp .env.example .env.local   # DEEPSEEK_API_KEY=...（UTF-8）
npm install
npm run dev
```

http://localhost:3000

生产构建：`npm run build && npm run start:prod`（127.0.0.1:3000）

| 变量 | 说明 |
|---|---|
| `DEEPSEEK_API_KEY` | 必填，仅服务端 |
| `DEEPSEEK_MODEL` | 可选，默认 `deepseek-chat` |
| `GATE_SLO_MIN` | 可选，运维看板 SLO 阈值，默认 `99` |

部署见 [docs/deploy-rocky9.md](./docs/deploy-rocky9.md)。
